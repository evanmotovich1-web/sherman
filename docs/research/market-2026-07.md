# Market research — Sherman's landscape, July 2026

Researched 2026-07-30 against the product as described in `README.md`,
`DESIGN.md`, and `AGENTS.md`. Sources are cited inline; primary sources
(vendor docs, specs, GitHub) were preferred and cross-checked against a
second source where feasible. Claims resting on a single secondary source
are marked as such.

## Executive summary

Sherman's core bet — a branded persona, a company skill set, and a Markdown
knowledge vault layered over someone else's coding CLI engine — is now a
recognizable market pattern, not an oddity. Three findings dominate:

1. **The skill format Sherman invented privately became a public standard.**
   Anthropic released Agent Skills as an open specification in December 2025
   (agentskills.io), and it has been adopted by 30+ tools including OpenAI
   Codex itself, which now natively discovers `SKILL.md` folders from
   `.agents/skills`. Sherman's `SKILL.md`-per-folder shape is exactly right;
   its front matter (`name`/`category`/`summary`) is a near-miss on the spec
   (`name`/`description`), and — more importantly — Sherman's skills today
   reach the launch screen but are not delivered to the engine through any
   standard channel.
2. **Sherman's Windows story is out of date.** Codex CLI shipped native
   Windows sandboxing (restricted tokens + ACLs, elevated/unelevated modes)
   around May 2026; WSL2 is a supported alternative, no longer the only
   route. `docs/WINDOWS.md`'s "WSL2 or nothing" framing was honest when
   written and is now stale.
3. **The enterprise knowledge-agent platforms (Glean, Dust, Onyx, Copilot
   Studio) compete on connectors, permission-aware search, and no-code agent
   builders — none of which Sherman needs at its size — but they validate
   the gaps Sherman should *not* copy and highlight what a lab back office
   actually buys: document control, training/competency tracking, and audit
   trails. Those are skill-shaped, PHI-free, and exactly in Sherman's lane.**

## 1. Branded internal agents built over coding CLIs

The "wrap a coding CLI in a company persona" pattern is now mainstream
practice rather than a product category with a single winner:

- Anthropic renamed the Claude Code SDK to the **Claude Agent SDK**
  (Sept 2025) explicitly to signal non-coding agent use — internal research,
  ops, and note-taking agents built on the same harness
  (https://claude.com/blog/building-agents-with-the-claude-agent-sdk,
  https://code.claude.com/docs/en/agent-sdk/overview). Anthropic's own
  engineering posts describe "agent harness" design as a discipline
  (https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents).
- The `CLAUDE.md`/`AGENTS.md` layering conventions Sherman uses (persona
  file assembled per-launch, engine-specific wrapper, memory as files) match
  documented best practice: Codex walks the filesystem reading every
  `AGENTS.md` from repo root down plus `~/.codex/AGENTS.md`
  (https://thepromptshelf.dev/blog/agents-md-codex-setup-guide-2026/);
  community guidance now recommends splitting the memory file into
  persona / rules / memory / decisions layers
  (https://redreamality.com/blog/claude-md-agents-md-deep-dive/).
- Open-source launchers and multi-agent TUIs exist in numbers — agent-deck
  (https://github.com/asheshgoplani/agent-deck), Mux
  (https://github.com/coder/mux), Emdash
  (https://github.com/generalaction/emdash) — but they are *session
  managers* for developers, not branded single-company operators. No
  directly comparable open project was found that does what Sherman does:
  one company identity, one vault, engine-swappable, non-developer-facing.
  That is a genuine (small) differentiation, with the caveat that the
  ingredients are now commodity.
- **OpenClaw** (formerly Clawdbot/Moltbot) is the closest spiritual peer:
  MIT-licensed, local-first, Markdown memory on disk, portable skill
  format, messaging-channel gateway (WhatsApp/Telegram/Slack/iMessage)
  (https://milvus.io/blog/openclaw-formerly-clawdbot-moltbot-explained-a-complete-guide-to-the-autonomous-ai-agent.md,
  https://docs.openclaw.ai/concepts/memory, https://openclaw.ai/). It is a
  *personal* agent, not a company one, but two of its patterns matter to
  Sherman: (a) its layered memory — durable `MEMORY.md` kept small and
  calm, plus messy per-day `memory/YYYY-MM-DD.md` notes that get
  consolidated upward — and (b) its channel gateway, which is a proven
  reference for Sherman's Phase-3 WhatsApp plan (already noted as a
  candidate in `DESIGN.md`).

**Takeaway:** the chassis is commodity; Sherman's moat is the vault
discipline, the honesty contract, and the company-specific skills — which
matches `AGENTS.md`'s own claim that "the skills and vault knowledge are
the product."

## 2. Company-knowledge agents

The platforms in this space, and what they trade against Sherman's shape:

- **Glean** — search-first enterprise platform, 100+ connectors,
  permission-aware indexing, SOC 2; roughly $45–65+/user/month all-in
  (https://dust.tt/blog/glean-alternatives-ai-enterprise-search,
  https://www.gosearch.ai/faqs/what-are-the-top-glean-alternatives/).
- **Dust.tt** — agent-first: no-code custom agents over company data,
  open source, ~$29/user/month
  (https://dust.tt/landing/glean, https://www.knowlee.ai/blog/dust-tt-alternatives-2026).
- **Onyx** (ex-Danswer) — MIT-licensed, self-hosted enterprise search +
  agents, 40+ connectors, MCP tool use; free community tier
  (https://onyx.app/insights/glean-alternatives).
- **Copilot Studio** — low-code agent builder, Microsoft-stack-first,
  requires Power Platform expertise
  (https://dust.tt/blog/microsoft-copilot-studio-alternatives).
- **Notion AI / Slack AI** — Q&A confined to their own silo; Slack AI
  "cannot create content" and "only searches Slack"
  (https://www.vellum.ai/blog/best-microsoft-copilot-alternatives,
  https://aibuzz.blog/notion-ai-vs-microsoft-copilot-vs-google-workspace-ai/).

**What they have that Sherman doesn't:** connectors to live systems (email,
drive, ticketing), permission-aware retrieval at scale, a web/mobile
surface, admin analytics, and vendor compliance attestations. **What
Sherman has that they don't:** a *writable*, human-auditable knowledge base
(one fact per file, in Git, with per-fact `user · session · date`
attribution); an agent that executes multi-step work locally rather than
answering questions; zero per-seat SaaS cost; and a hard, structural no-PHI
boundary instead of a compliance checkbox. For a company of Sherman Abrams
Labs' size, the per-seat platforms are overkill and their PHI posture
(indexing everything) is exactly what Sherman is designed to avoid. The one
pattern worth borrowing is their emphasis on **provenance and freshness**
of knowledge — stale-document detection is a headline feature in this
category, and Sherman's vault has no review-date machinery yet.

## 3. Agent skill / persona ecosystems

- **Agent Skills is an open standard.** Released by Anthropic 2025-12-18,
  spec at https://agentskills.io/specification, governed openly
  (https://github.com/agentskills/agentskills). Frontmatter: `name`
  (required; lowercase/digits/hyphens, must match the directory name) and
  `description` (required, 1–1024 chars, "what it does and when to use
  it"); optional `license`, `compatibility`, `metadata` (arbitrary
  key-value map), and experimental `allowed-tools`. Layout: `SKILL.md` plus
  optional `scripts/`, `references/`, `assets/`. Loading is by progressive
  disclosure: name+description at startup (~100 tokens), full body on
  activation, referenced files on demand. A reference validator exists
  (`skills-ref validate`).
- **Adoption is broad**: Claude Code, Codex, Cursor, VS Code/Copilot,
  Gemini CLI, Goose, OpenCode, JetBrains Junie and dozens more list on the
  spec's client showcase (https://agentskills.io); secondary reporting
  counts 30+ tools by March 2026
  (https://thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards/,
  https://www.paperclipped.de/en/blog/agent-skills-open-standard-interoperability/).
  Marketplaces exist (Vercel's skills.sh; community indexes claim
  1M+ scraped skills — single-source figures, treat as directional:
  https://agentman.ai/blog/agent-skills-ecosystem-report-2026).
- **Codex reads skills natively** (primary source:
  https://developers.openai.com/codex/skills/ →
  https://learn.chatgpt.com/docs/build-skills): it scans `.agents/skills`
  from the working directory up to repo root, plus `$HOME/.agents/skills`,
  `/etc/codex/skills`, and built-ins; explicit invocation is `$skill-name`,
  implicit invocation matches on the `description` field.
- **Sherman's gap:** its frontmatter uses `category` + `summary` (see
  `skills/README.md` and `shell/src/registry.js`), which no other tool can
  read, and — verified in source — the launcher (`bin/sherman`) never
  delivers `skills/` to the engine: skills appear on the launch screen, and
  the eval turn points at `skills/` by path (`shell/src/commands.js`), but
  an ordinary engine turn has no skill discovery at all. Meanwhile the
  engine Sherman already runs would do progressive disclosure for free if
  the skills sat in the workspace's `.agents/skills`. Sherman's
  hand-maintained, verified `agent/capabilities.json` has no ecosystem
  equivalent — the honest-registry idea is ahead of the market — but the
  skill *format* is behind it.

## 4. Small-lab / clinic back-office tooling (PHI-free workflows)

What labs actually buy for the back office, per vendor positioning and
CLIA/CAP requirements — all of it document- and workflow-shaped, none of it
requiring patient data:

- **Document control** is the anchor product: version control, electronic
  signatures, approval workflows, periodic review cycles, and audit
  readiness for CAP/CLIA (MediaLab by Vastian:
  https://www.vastian.com/laboratories/solutions/policy-and-document-management;
  SimplerQMS: https://simplerqms.com/laboratory-quality-management-system/).
  CAP/CLIA/ISO 15189 all require that staff operate under *current,
  approved* versions of procedures — meaning effective dates, review-due
  dates, and owners are first-class metadata, not decoration.
- **Personnel training and competency assessment** is the second anchor:
  CLIA requires six specific competency elements per test per person,
  assessed at 6 months and 1 year for new staff, then annually
  (CMS brochure:
  https://www.cms.gov/Regulations-and-Guidance/Legislation/CLIA/Downloads/CLIA_CompBrochure_508.pdf;
  https://staffready.com/2026/06/17/closing-the-gaps-are-all-six-clia-elements-truly-covered/).
  Tools like MediaLab, StaffReady, and mylabcompliance
  (https://mylabcompliance.io/lab-compliance-software) sell exactly this
  tracking; Trainual sells the SMB version — role-based SOP assignment,
  onboarding checklists, proof-of-completion
  (https://trainual.com/solution/health-medical).
- Broader QMS scope: change management, deviation/CAPA logs, complaint
  handling
  (https://www.accountablehq.com/post/best-practices-for-compliance-documentation-in-clinical-laboratories).

**Takeaway:** Sherman's `sop-draft` and `company-document` skills sit at
the entrance of this space. The evidence says the *rest* of the lab
back-office stack — SOP review cycles, training/onboarding checklists,
competency-assessment scaffolding (the framework and tracking templates,
with the actual assessment records staying in the lab's approved HR/QMS
system if they name employees performing patient testing) — is the
highest-value direction for new skills, and none of it touches PHI.

## 5. Security and sandboxing for agents on user machines

Cross-verified against
https://medium.com/@Koukyosyumei/how-claude-code-and-codex-sandbox-untrusted-code-ba39b493046a,
https://code.claude.com/docs/en/sandboxing,
https://codex.danielvaughan.com/2026/07/18/codex-cli-windows-sandbox-architecture-powershell-ast-safety-elevated-unelevated-appcontainer-restricted-tokens/,
and https://itecsonline.com/post/how-to-install-codex-cli-on-windows-2026-guide:

- **macOS:** Seatbelt via `sandbox-exec` with `.sb` policy files is the
  standard both Claude Code and Codex use — the same mechanism Sherman's
  launcher already applies and escape-tests. Sherman is aligned with the
  state of the art here.
- **Linux:** the current pattern is bubblewrap (namespaces) + seccomp
  syscall filtering, with Landlock as fallback; Codex uses Landlock +
  seccomp. Sherman has never run on Linux; when it does, this is the
  recipe to follow, and both engines already ship it.
- **Windows:** the big change. OpenAI shipped native Windows support for
  Codex (reported May 2026) with OS-level sandboxing built on **restricted
  tokens + filesystem ACLs**, in two modes — *elevated* (dedicated sandbox
  users + firewall rules, recommended) and *unelevated* (restricted token
  derived from the current user). WSL2 remains supported but is no longer
  the default
  (https://medium.com/@ofox96326/codex-cli-on-windows-wsl2-vs-native-install-which-one-should-you-pick-191e32f73851,
  https://codex.danielvaughan.com/2026/04/01/codex-cli-windows-native-sandbox-wsl/).
  Claude Code's Windows sandboxing similarly uses restricted token + Job
  Object + WFP network filtering (single technical source; verify in
  Anthropic docs before relying on it).
- Common design across all three platforms: default-deny network from the
  sandboxed process, writable roots scoped to the workspace, protected
  metadata (`.git`, `.codex`, `.agents`) forced read-only. Sherman's
  "writes confined to vault + workspace, engine network egress denied" is
  the same policy expressed one level up.

**Implication:** Sherman's write-boundary need not be macOS-only forever,
and `docs/WINDOWS.md`'s premise ("the one route worth trying is WSL2") is
now factually behind the engine it wraps.

## What Sherman's shape gets right

- **Skills-as-folders with one `SKILL.md` each** — independently converged
  on what became the industry's open standard; only the frontmatter
  dialect differs.
- **Markdown-files-as-memory, one fact per file, in Git** — the same
  local-first, no-hidden-state pattern that made OpenClaw the
  fastest-growing agent project of 2026, plus per-fact attribution lines
  that none of the surveyed products do.
- **Riding the engine's own OAuth and sandbox** instead of building either
  — both engines now invest heavily in exactly the kernel-level sandboxing
  Sherman depends on.
- **The honest launch screen** (`capabilities.json` verified by smoke
  check, "0 skills" rendered as 0) — the surveyed ecosystem has
  marketplaces with a million scraped skills and no verification story;
  a registry that refuses speculation is a real differentiator in kind.
- **The structural no-PHI floor** — enterprise knowledge platforms index
  everything and then bolt on permissions; Sherman's refusal to ingest PHI
  at all is the only posture that is safe *by construction* for a
  diagnostics company running a non-HIPAA system.
- **Thin engine adapters over one canonical persona** — matches the
  documented layering best practice for `CLAUDE.md`/`AGENTS.md` products.

## Ranked improvements

Constraints respected: no PHI, no Phase-3 scope (no vault service, no
WhatsApp, no employee onboarding *system* — an onboarding *skill* that
drafts checklists is company-document work, not Phase-3 infrastructure),
engine stays Codex/Claude Code.

1. **Make `SKILL.md` frontmatter Agent Skills-spec compliant.** Add the
   required `description` field (what + when, trigger keywords) to all nine
   skills and move `category`/`summary` under the spec's `metadata` map (or
   keep them as extra keys the shell reads); names already match their
   directories.
   *Rationale:* the format Sherman privately invented is now an open
   standard read by 30+ tools including both of Sherman's engines; a
   two-key rename buys interoperability (https://agentskills.io/specification).
   *Effort:* small (9 files + `registry.js` parser + `skills/README.md` +
   smoke check 17).

2. **Deliver skills to the engine natively via `.agents/skills`.** Have
   `bin/sherman` symlink (or copy) the repo's `skills/` into
   `~/.sherman/workspace/.agents/skills` at adapter-assembly time, so Codex
   discovers them with progressive disclosure and `$skill-name` invocation;
   Claude Code reads the same standard when that backend lands.
   *Rationale:* verified in source — today skills reach the launch screen
   but no ordinary engine turn ever sees them; the engine already ships
   the loading machinery for free
   (https://learn.chatgpt.com/docs/build-skills).
   *Effort:* small–medium (launcher change + smoke check that the
   workspace link exists and resolves; depends on #1).

3. **Rewrite `docs/WINDOWS.md` for the native Codex Windows sandbox.**
   Document the elevated/unelevated restricted-token modes as the primary
   route, demote WSL2 to the alternative, and state plainly that Sherman's
   own launcher still hasn't run there.
   *Rationale:* Codex shipped native Windows sandboxing (~May 2026); the
   doc's "WSL2 is the one route" premise is stale, and Sherman's contract
   is that stale claims get corrected
   (https://codex.danielvaughan.com/2026/04/01/codex-cli-windows-native-sandbox-wsl/).
   *Effort:* small (docs only; no code).

4. **Add document-control metadata to SOP vault files, plus a stale-SOP
   report skill.** Extend the `sop-draft` skill so every SOP carries
   effective date, owner, version, and next-review date; add a small skill
   that scans `vault/wiki/` and reports SOPs past review.
   *Rationale:* review cycles and current-version control are the anchor
   feature of every lab compliance product and a CAP/CLIA expectation —
   and Sherman's vault already stores the files, it just lacks the dates
   (https://www.vastian.com/laboratories/solutions/policy-and-document-management).
   *Effort:* medium (skill edits + one new skill; no new infrastructure).

5. **Add a `training-checklist` skill (role-based onboarding/training
   documents).** Drafts role-scoped training checklists and
   proof-of-completion templates from the vault's SOPs, in the company
   format — documents for humans to run, not an onboarding system.
   *Rationale:* role-based SOP training assignment is what SMB tools like
   Trainual sell to clinics, it is pure document work, and it composes
   directly with #4 (https://trainual.com/solution/health-medical).
   *Effort:* medium (one skill + a vault format page).

6. **Add a CLIA competency-assessment scaffolding skill.** Generates the
   six-element assessment framework and blank tracking templates per test
   system, with an explicit warning that completed assessments naming
   staff performing patient testing belong in the lab's approved QMS,
   not the vault.
   *Rationale:* the six-element/annual-cadence requirement is regulatory,
   universal, and template-shaped — the exact niche StaffReady and
   MediaLab monetize
   (https://www.cms.gov/Regulations-and-Guidance/Legislation/CLIA/Downloads/CLIA_CompBrochure_508.pdf).
   *Effort:* medium (one skill with reference material).

7. **Adopt the layered-memory consolidation pattern for the vault inbox.**
   Add a skill (or extend `session-eval`) that periodically sweeps
   `vault/inbox/` and session-dated notes, promoting durable facts into
   `wiki/`/`memory/shared/` and pruning what aged out — OpenClaw's
   "daily notes are messy, MEMORY.md stays small and calm" discipline.
   *Rationale:* the most successful local-first agent of 2026 converged on
   explicit consolidation as the thing that keeps file-based memory usable
   over months (https://docs.openclaw.ai/concepts/memory).
   *Effort:* medium (one skill; no schema change).

8. **Run the spec's `skills-ref validate` in smoke check 17.** Once #1
   lands, validate every skill against the reference library (vendored or
   reimplemented in the existing no-framework style) instead of only the
   name-matches-directory check.
   *Rationale:* smoke.sh already refuses to advertise broken skills;
   validating against the public spec makes that guarantee portable
   (https://github.com/agentskills/agentskills).
   *Effort:* small (extend one smoke check).
