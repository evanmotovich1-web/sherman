<objective>
## Goal

Build the engine layer the Sherman Shell will sit on: one `EngineSession`
contract, one **real** backend driving Codex headless via `codex exec --json`
+ `codex exec resume`, one Claude stub that fails with a clear message, and a
permissions posture that confines the engine to the vault at the OS level.

No UI in this plan. The deliverable is a headless session you can hold a real
multi-turn conversation with from the command line.

## Purpose

Today `sherman` ends with `exec codex` and the user lands in OpenAI's chrome.
That is not Sherman. Sherman must own the screen the way Hermes does — our UI
on top, the engine running headless underneath (design doc §3c).

The UI is the visible half, but the engine seam is the load-bearing half and
the only half that can fail in ways a screenshot won't show. Proving a real
Codex turn, real multi-turn memory, real token accounting, real interrupts and
a real data boundary FIRST means Plan 04-02 can build the Ink UI against a
contract that is already known to work.

This is also where the §3 either-engine promise moves from the chrome seam to
the UI seam: one interface, two backends, engine specifics quarantined behind
it — exactly as `agent/SYSTEM.md` + adapters did for the persona.

## Output

- `shell/` — a dependency-free Node package (Ink arrives in 04-02)
- `EngineSession` contract + engine-agnostic normalized event stream
- Working Codex backend, verified against real Codex on this machine
- Claude stub backend that implements the contract and refuses clearly
- `shell/README.md` documenting the transport decision and the safety posture
</objective>

## Verified engine facts — probed on this machine, do NOT re-derive

Codex `codex-cli 0.145.0`, Node `v22.23.1`, `~/.sherman/config.json` →
`{"version":1,"engine":"codex","user":"evan-motovich","vault_path":"/Users/moto/code/sherman/vault"}`

**Event stream** — `codex exec --json` emits exactly this JSONL shape:

```json
{"type":"thread.started","thread_id":"019f9ce8-af8b-71b3-bc72-41b2ca2d2bcb"}
{"type":"turn.started"}
{"type":"item.completed","item":{"id":"item_0","type":"agent_message","text":"PONG"}}
{"type":"turn.completed","usage":{"input_tokens":39245,"cached_input_tokens":19200,"cache_write_input_tokens":0,"output_tokens":128,"reasoning_output_tokens":79}}
```

**Multi-turn works.** `codex exec resume <thread_id> "<prompt>" --json` reuses
the thread — verified by the model correctly recalling a word from the previous
turn, with `cached_input_tokens: 19200` confirming prompt reuse.

**No token deltas.** A 128-token answer arrived as ONE `item.completed`, ~5.5s
after `turn.started`. Streaming is item-level, not token-level. This is the
accepted trade-off (see the decision record below).

**TRAP 1 — stdin.** `codex exec` reads stdin when stdin is not a TTY and will
hang printing `Reading additional input from stdin...`. Child processes MUST be
spawned with stdin ignored.

**TRAP 2 — flag asymmetry.** `codex exec resume` does **not** accept `-s/--sandbox`,
`-C/--cd`, `--add-dir`, or `-p/--profile`. It DOES accept `-c key=value`,
`--enable/--disable`, `-m`, `--json`, `--skip-git-repo-check`. Every setting that
must hold on turn 2+ therefore has to be expressed as `-c` overrides, and cwd has
to come from the Node spawn option — never `-C`. Getting this wrong makes the
posture silently different on the first turn than on all later turns.

**Config keys validated** under `--strict-config` (which errors on unknown fields):
`sandbox_mode="workspace-write"` and
`sandbox_workspace_write.writable_roots=["<path>"]` both parse.

**cwd vs AGENTS.md — resolved.** Codex reads `AGENTS.md` from its cwd, so cwd must
be `~/.sherman/workspace` (where `bin/sherman` assembles the adapter). The sandbox
boundary is then supplied by `writable_roots`, not by cwd. Do not set cwd to the
vault — it would orphan the system prompt.

<decision_record>
## D8 — Codex transport: `codex exec --json` + `exec resume`, not app-server

**Chosen** (Evan, at plan time, after being shown probe evidence for both).

`codex exec --json` is a stable CLI surface, verified working end-to-end on this
exact Codex version, with multi-turn resume and free token accounting.

`codex app-server` was the alternative. Its v2 protocol does expose
`AgentMessageDeltaNotification` (`{delta, itemId, threadId, turnId}`) — real
token-by-token streaming — but it is marked `[experimental]`, carries 39+ message
types, needs a JSON-RPC handshake that was NOT verified, and can break on any
Codex update. Building v1 on it risks the whole shell breaking on `codex update`.

**Cost accepted:** no typewriter effect. Mitigation is the UI's job in 04-02 (a
live activity indicator + elapsed timer so a wait never reads as a dead screen).
Multi-step turns still fill progressively because reasoning, tool calls and
messages each arrive as they complete — it is only a single short answer that
lands all at once.

**Not a lock-in:** the whole point of `EngineSession` is that swapping to
app-server later touches one file and no UI code.

## D9 — The vault boundary is enforced by the OS sandbox, not by removing shell

The brief asks for "no shell exec". Stated plainly: on Codex that instruction
is in tension with the same requirement's first half, because Codex delivers file
read/search/write *through* its shell and `apply_patch` tools (`shell_tool` is a
feature flag and can be disabled, but doing so would strip file access — the
capability Sherman actually needs — and leave the agent unable to read the vault
at all).

So the boundary is implemented where it is actually enforceable: the macOS
seatbelt sandbox. Shell commands may run, but the OS denies every read/write
outside the permitted roots and blocks network egress. That is a *stronger*
company-data boundary than a tool allow-list, because it cannot be talked around
by the model, and it satisfies the real requirement in the brief and §4: nothing
outside the vault, nothing auto-approved, no exfiltration path.

This is a deliberate strengthening, not a weakening. Task 3 must **prove** it
rather than assert it. If the escape test in AC-6 fails, the posture is wrong and
the plan is not done — do not paper over it.
</decision_record>

<task type="auto">
  <name>Task 2: Codex backend — exec --json, resume, normalized events, interrupt, vault posture</name>
  <files>shell/src/engine/codex.js</files>
  <action>
    Implement the Codex backend against the verified facts in `<context>`. Read them
    first — they were probed on this machine and are not to be re-derived or guessed.

    **Process model.** One `codex` child process per turn, spawned with
    `node:child_process.spawn`. Turn 1 is `codex exec --json <prompt>`. Every later
    turn is `codex exec resume <threadId> --json <prompt>`, where `threadId` came
    from the `thread.started` event of turn 1. Hold `threadId` in memory only —
    do NOT persist it under `~/.sherman/workspace/`, which is disposable by design
    (PROJECT.md R10). Cross-run history is out of scope for v1.

    **stdin MUST be ignored** — `stdio: ['ignore', 'pipe', 'pipe']`. Without this
    codex blocks reading stdin (TRAP 1). This is the single most likely way to end
    up staring at a hung shell.

    **cwd** = `config.workspacePath` (`~/.sherman/workspace`), passed as spawn's
    `cwd` option, never `-C` (TRAP 2 — `-C` does not exist on resume). This is what
    makes codex pick up the assembled `AGENTS.md` as its system prompt, which is
    the whole point of the adapter that `bin/sherman` already builds.

    **Permissions posture — identical flags on turn 1 and every resume.** Build the
    argv from ONE shared function so the two code paths cannot drift:
    - `--json`
    - `--skip-git-repo-check` (the workspace is not a git repo)
    - `-c sandbox_mode="workspace-write"`
    - `-c sandbox_workspace_write.writable_roots=["<vaultPath>"]`
    - an approval policy set to never, so nothing escalates to a human and nothing
      outside the sandbox is auto-approved
    Validate every `-c` key against `--strict-config` while developing; if a key
    name differs on this Codex version, find the correct one and record it in the
    README rather than dropping the setting. NEVER pass
    `--dangerously-bypass-approvals-and-sandbox` or `--dangerously-bypass-hook-trust`.

    **Parsing.** Read stdout line-by-line (`node:readline` over the stream — do not
    split a raw chunk buffer on newlines; a JSON object can straddle a chunk
    boundary and you will corrupt it under load). Map:
    - `thread.started` → capture `thread_id`; no event emitted
    - `turn.started` → `{kind:'turn-start'}`
    - `item.completed` with `item.type === 'agent_message'` → `{kind:'message', text: item.text}`
    - `item.completed` with a reasoning item type → `{kind:'reasoning', text}`
    - `item.completed` with any other item type → `{kind:'tool', label}` with a
      short human-readable label
    - `turn.completed` → `{kind:'turn-end', usage}` mapping codex's snake_case
      usage keys to the normalized camelCase shape and computing `total`
    - anything unrecognized → ignore silently, do not crash. The event set will grow
      with future codex versions; an unknown `type` must never take the shell down.
    Malformed JSON on a line → skip that line, do not throw.

    **Errors.** Non-zero exit → `{kind:'error'}` including captured stderr, trimmed
    to something a person can read. Missing `codex` binary (ENOENT) → an error event
    saying codex is not installed, matching the launcher's existing install hint.

    **interrupt().** Terminate the child (SIGTERM), emit `{kind:'interrupted'}`,
    resolve the in-flight iterator cleanly — no unhandled rejection, no orphan.
    Keep `threadId` so the next `send()` resumes the same conversation. Note the
    pleasant property of the per-turn process model: an interrupt is just a killed
    process, and the thread survives because codex persists it server-side.

    **Usage accounting.** Accumulate per-turn usage into a session running total for
    04-02's status bar (AC-5).

    **model** for `SessionInfo` is best-effort display only: use an explicitly passed
    model if set, else fall back to a neutral label like "codex default". Do not
    invent a value and do not pass `-m` to force one — that would silently override
    Evan's own codex model choice.
  </action>
  <verify>

    A two-prompt probe in one process ("Remember the word BANANA." then "What word

    Interrupt: start a long turn, call interrupt(), confirm an interrupted event,

    and a subsequent send() still answers on the same thread.

    `grep -rn "dangerously" shell/` returns nothing.
