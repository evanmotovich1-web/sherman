<objective>
## Goal

Typing `sherman` lands in a branded Sherman screen. No OpenAI chrome, no
Anthropic chrome — our header, our chat pane, our status bar, with the engine
running headless underneath through the 04-01 `EngineSession`.

`sherman --raw` still launches the engine directly, for debugging.

## Purpose

This is the half of §3c the user actually sees, and it closes the gap Evan named
after his first live run: Sherman was branded up to the banner and unbranded
after it.

It also carries a requirement Evan called out explicitly and which is **not
deferrable**: the activity indicator with elapsed time. Given D8 there are no
token deltas — a short answer lands all at once after a multi-second pause, and
the first turn is the slowest one a user ever sees (~19,900 input tokens, nothing
cached until turn 2). Without a live indicator the shell reads as *hung* on the
very first impression, and would feel slower than raw Codex while being no
slower. Perceived speed is part of the UI here, not polish on top of it.

## Output

- An Ink app: header, scrollback transcript, composer, status bar, thinking indicator
- `bin/sherman` execs the shell; `sherman --raw` execs the engine
- `install.sh` installs shell dependencies
- `smoke.sh` extended by 3 checks (and 2 existing checks adapted — see Task 3)
</objective>

## Verified UI facts — probed on this machine, do NOT re-derive

Ink `7.1.1`, React `19.2.8`, Node `v22.23.1` (Ink 7 requires Node >=22 — satisfied).

**Ink 7 exports:** `Box, Newline, Spacer, Static, Text, Transform, measureElement,
render, renderToString, useAnimation, useApp, useBoxMetrics, useCursor, useFocus,
useFocusManager, useInput, useIsScreenReaderEnabled, usePaste, useStderr, useStdin,
useStdout, useWindowSize`. There is **no built-in text input** — that is a separate
package.

**The banner renders correctly inside Ink.** Verified with `renderToString`: raw
256-color escapes survive untouched, all 18 lines preserved, display width measured
correctly at 41 columns despite the multi-byte block glyphs. No pre-processing,
no stripping, no width workaround needed.

**`logo/banner.ans` is 41 columns x 18 lines**, house colors confirmed present:
`38;5;205` pink, `38;5;135` purple, `38;5;39` blue, `38;5;196` red. The parallel
Codex session's redesign is committed, so the file is settled.

**Two-stage Ctrl+C works** — proven in a real pty with `script -q /dev/null`.
`render(<App/>, {exitOnCtrlC: false})` lets `useInput` observe
`key.ctrl && input === 'c'`. First press stopped the spinner, second exited clean.

**`useAnimation({interval, isActive})` returns `{frame, time, delta, reset}`** —
spinner frame index AND elapsed milliseconds from one hook. The thinking indicator
needs no manual `setInterval`. Verified rendering `⠦ thinking… 1.3s`.

**`alternateScreen` must NOT be used.** Ink's own docs state the terminal's
scrollback buffer is unavailable in the alternate screen. The brief asks for
scrollback, so the app stays on the primary screen and commits history via
`<Static>`.

**Node is at `~/.local/bin/node`, symlinked to `~/.hermes/node/bin/node`** — not a
version-manager shim, and present in a minimal PATH. Note it is supplied by
Hermes' bundled runtime, so Sherman now has a hard Node dependency that Phase 1
did not have.

**Ink throws on non-TTY stdin:** `Raw mode is not supported on the current
process.stdin`. This matters for smoke — see the trap in Task 3.

<decision_record>
Decisions made at plan time. Flagged in the report so they can be overridden
before APPLY rather than discovered afterward.

## D11 — Build the composer with `useInput`, do not add `ink-text-input`

Ink 7 ships no text input. `ink-text-input@6` declares `peerDependencies: {ink:
'>=5'}`, which *permits* Ink 7 without being tested against it. A chat composer
needs typing, backspace, submit and paste — roughly forty lines against
`useInput`, with `usePaste` available for paste. Taking an unverified dependency
for that is the worse trade, and it would be the only third-party UI package in
the tree.

## D12 — Primary screen with `<Static>`, never `alternateScreen`

`<Static>` writes committed transcript items out permanently and Ink stops
managing them, so the terminal's own scrollback holds the conversation and mouse
wheel / `Cmd-F` work as users expect. The alternate screen would give a tidier
full-window layout and destroy scrollback doing it. Scrollback was in the brief;
a tidy layout was not.

## D13 — Full banner once at the top, compact header pinned

The banner is 18 lines. On a 24-row terminal, pinning it leaves six rows for the
actual conversation. So the full mark renders once as the launch moment (and
scrolls away naturally, exactly as `bin/sherman` already behaves today), while a
single compact line stays visible in the chrome. This is the "small variant
acceptable" the brief allowed, chosen for a concrete reason rather than taste.

## D14 — Missing or too-old Node fails loudly; it never silently falls back

If Node is absent or older than 22, `bin/sherman` prints what is wrong, how to
fix it, and mentions `sherman --raw` — then exits non-zero. It does **not** quietly
exec the engine instead. A silent fallback would drop the user into OpenAI chrome
while they believe they are in Sherman, which is the precise failure this whole
phase exists to remove. The escape hatch stays available, but the user chooses it.
</decision_record>

<task type="auto">
  <name>Task 2: The live turn — chat loop, thinking indicator with elapsed time, two-stage Ctrl+C</name>
  <files>shell/src/ui/app.js, shell/src/ui/Thinking.js, shell/bin/sherman-shell.js</files>
  <action>
    This task carries Evan's non-deferrable requirement. Build the indicator first,
    not last — if it slips it will not get done, and AC-5 is the difference between
    a shell that feels alive and one that reads as hung on its slowest turn.

    `Thinking.js` — the activity indicator. Drive it with
    `useAnimation({interval: 80, isActive})`, which returns `{frame, time}`: `frame`
    indexes the spinner glyphs, `time` is elapsed milliseconds. No manual
    `setInterval`, no `Date.now()` bookkeeping. Show a braille spinner, the elapsed
    seconds to one decimal, and the current activity label. Default the label to
    "thinking", and replace it from the latest `reasoning` or `tool` event so a
    multi-step turn narrates itself instead of showing a generic word for 30
    seconds. Use the red accent sparingly; this element appears constantly and
    should not shout.

    `app.js` — the root component and the only place turn state lives:
    - Committed transcript array (feeds `<Static>`), plus the in-flight turn's
      partial output rendered in the live region.
    - `submit(text)`: push the user message, set busy, then iterate
      `session.send(text)` mapping the 04-01 event union — `turn-start`,
      `reasoning`, `message`, `tool`, `turn-end`, `interrupted`, `error`. Handle
      every kind and ignore unknown ones, matching the backend's own tolerance;
      an event kind added by a future codex must not crash the UI.
    - The indicator must mount on submit, before the first event arrives. Do not
      gate it on `turn-start` — the whole point is covering the dead time at the
      start of a turn, which on turn 1 is the longest wait in the product.
    - On `turn-end`, commit the turn to the transcript, clear busy, refresh usage.
    - On `error`, render it as a transcript item and clear busy. The Claude stub's
      not-implemented message must display as ordinary text, not a crash (04-01
      built it to make this work).

    Two-stage Ctrl+C at app level, proven working in a pty:
    - `render(..., {exitOnCtrlC: false})` in the entry point, so Ink does not exit
      on its own and `useInput` can see the key.
    - First Ctrl+C while busy → `session.interrupt()`, note it in the transcript,
      clear busy. The shell stays up and the thread survives (04-01 verified this).
    - Ctrl+C when not busy → `session.dispose()` then `exit()`. Clean, no trace.
    - Track the stage in state so a second press during the same wait still exits
      rather than interrupting an already-dead turn.

    `shell/bin/sherman-shell.js` — replace the "UI is not built yet" default path
    with the Ink app. Keep `--version`, `--help` and `--probe` working exactly as
    they are; `--probe` stays the diagnostic that separates engine faults from
    render faults, and 04-01's README promises it.

    Before rendering, guard the environment (AC-8): if `process.stdin.isTTY` is
    falsy, print a clear message and exit non-zero rather than letting Ink throw
    `Raw mode is not supported`. This guard is also what keeps a piped smoke run
    from hanging.
