## Goal

Make `sherman` a working command on this Mac. Typing it shows the launch
screen, then drops into a real Claude Code session whose context carries
Sherman's persona, both vault paths, the operator's name, and the no-PHI rule.

## Purpose

This is the chassis for the whole product (PROJECT.md R1–R7). Until `sherman`
launches, there is nowhere for the skills — which are the actual product — to
live. It also fixes the one-definition/two-adapters shape early, which is what
keeps the either-engine promise from quietly becoming Claude-only.

  <files>.gitignore, agent/SYSTEM.md, adapters/claude-code/CLAUDE.md, adapters/codex/AGENTS.md</files>
  <action>
    `git init` in /Users/moto/code/sherman (local only — never push, PROJECT.md C5).

    Create the directory skeleton: `bin/ agent/ adapters/claude-code/
    adapters/codex/`. Also `mkdir -p logo vault/wiki vault/memory/shared
    vault/memory/private` — **empty dirs only**. Creating or editing any FILE
    under logo/ or vault/ is out of bounds (see boundaries); the Codex session
    owns their contents. The mkdir exists so the adapter's paths resolve on day
    one regardless of that track's progress.

    **agent/SYSTEM.md — the persona.** This is the one definition of who
    Sherman is (PROJECT.md R5). Write it as a system prompt addressed to the
    agent, not as documentation about the agent. It must establish:

    - Identity: the operations agent for Sherman Abrams Labs, a family medical
      diagnostics company.
    - Voice: plain, professional, direct. Answer the question asked. No

    - Knowledge location: its knowledge lives in the vault, not in its weights.

      from. When it learns a durable new company fact, write it to the vault:
      one fact per file.
    - Scope: company operations work. Not a general coding assistant.

    Then the **HARD RULE**, stated at maximum salience — set apart, its own
    heading, unmissable. Wording must carry all of this:

    > Never store, request, repeat, or process patient-identifying information.
    > This vault holds procedures, SOPs, formats, and company knowledge only —
    > never patient records, never results tied to a named patient, never
    > anything that could identify a patient. If a request would require
    > patient-identifying data, refuse it and say why: this system is not
    > HIPAA-compliant for PHI, and PHI must never enter it at all.

    The word "patient" appearing here is load-bearing — AC-5 and smoke check 3
    both assert on it.

    **The two adapter templates.** Each is an engine-specific *wrapper* around
    a single placeholder line — exactly this token, alone on its own line:

        {{SHERMAN_BODY}}

    bin/sherman generates the body once (Task 2) and splices it in, so the
    persona and the memory blocks exist in exactly one place. Do NOT paste the
    persona or the memory blocks into these templates — that duplication is the
    specific failure this design exists to prevent.

    Around the token, each template carries only what differs by engine:
    - `adapters/claude-code/CLAUDE.md` — framed as Claude Code project context,
      opening with a line establishing this file IS the Sherman configuration
      for this session and is regenerated on every launch, so edits here are
      lost (edit agent/SYSTEM.md in the repo instead).
    - `adapters/codex/AGENTS.md` — same contract in AGENTS.md idiom.

    Keep both wrappers short. The body is the substance.
  </action>

<task type="auto">
  <name>Task 2: bin/sherman — banner, first-run wizard, adapter assembly, exec</name>
  <files>bin/sherman</files>
  <action>
    `#!/usr/bin/env bash` + `set -euo pipefail`. **bash 3.2 only** (PROJECT.md
    C4): no `${var,,}` — use `tr '[:upper:]' '[:lower:]'`; no `readlink -f`; no
    associative arrays.

    **Resolve repo root from $0**, chasing symlinks with a portable
    `while [ -L "$src" ]` loop (the install puts a symlink on PATH, so `$0` is
    usually a link). Root = dirname of bin/ . Must work both via the symlink
    and when smoke.sh runs `bin/sherman` directly.

    **All state under `${HOME}/.sherman`** — read `$HOME` every time, never
    hardcode `/Users/moto`. smoke check 2 overrides HOME; a hardcoded path
    silently defeats it and, worse, scribbles on the real config.

    Order of operations:

    1. **Launch screen.** If `$ROOT/logo/banner.ans` exists, `cat` it verbatim
       (ANSI passes through untouched). Otherwise print a plain-text
       placeholder — "SHERMAN ABRAMS" plus a one-line subtitle. Never fail and
       never warn because the logo is missing; the logo track is still running.

    2. **If `$HOME/.sherman/config.json` does not exist**, run the wizard:

       a. Prompt exactly: `Sign in with: [1] Anthropic  [2] OpenAI`
          Read the answer. `1` → engine `claude`. `2` → engine `codex`.
          Reject anything else and re-prompt. Ask nothing else about auth —
          Sherman performs no OAuth (PROJECT.md R3); the engine's own native
          browser login fires on first launch if it is unauthenticated.

       b. `command -v` the engine binary. If missing, print its official
          install command and `exit 1` **before writing any config** (AC-3):
            claude → `curl -fsSL https://claude.ai/install.sh | bash`
                     (note the npm alternative: `npm install -g @anthropic-ai/claude-code`)
            codex  → `npm install -g @openai/codex`

       c. Ask the operator's name. Slugify for filesystem safety: lowercase via
          `tr`, spaces → `-`, drop everything outside `[a-z0-9_-]`. Re-prompt if
          the result is empty.

       d. `mkdir -p "$VAULT/memory/private/$USER_SLUG"` — plus `-p` on
          `$VAULT/wiki` and `$VAULT/memory/shared` so adapter paths always
          resolve. Directories only; write no files there.

       e. Write `$HOME/.sherman/config.json` with `printf`:
          `{"version":1,"engine":"...","user":"...","vault_path":"..."}`
          `vault_path` defaults to `$ROOT/vault`. Recording it as a field is
          what makes the Phase-3 swap to a network backend a config change
          rather than a rewrite (PROJECT.md R6).

       Then fall through into the normal launch — first run continues into a
       session, it does not stop and tell you to run the command again.

    3. **Load config.** Parse with `/usr/bin/jq -r` (system jq, HOME-independent
       — do not use the pyenv python3 shim, it breaks under HOME override).
       Fall back to a `sed` extraction only if jq is absent.

    4. **Assemble the adapter.** Every launch, unconditionally — the repo is the
       source of truth and the workspace is disposable.

       `mkdir -p "$HOME/.sherman/workspace"`, then **remove both** `CLAUDE.md`
       and `AGENTS.md` from it before writing. Removing both matters: switching
       engines otherwise leaves a stale sibling that the other engine may read.

       Build the body in a temp file, in this exact order:
         i.   full contents of `$ROOT/agent/SYSTEM.md`
         ii.  the knowledge-base block naming `<vault_path>/wiki` and
              `<vault_path>/memory/shared` — search before answering company
              questions; write durable new facts there, one fact per file
         iii. the private-memory block naming
              `<vault_path>/memory/private/<user>` — personal context goes
              there and NOWHERE else
         iv.  the no-PHI hard rule, restated in full (deliberate repetition —
              it is the last thing in the file and the compliance floor)

       Splice the body into the template wherever `{{SHERMAN_BODY}}` appears.
       **Use `awk`**, printing template lines until the token, then the body
       file, then the rest. Do NOT use `sed` substitution — the body is
       multi-line markdown full of `&`, `/` and backslashes, all of which are
       special on sed's replacement side. This is a known trap; awk sidesteps
       it entirely.

       Template selection: engine `claude` → `adapters/claude-code/CLAUDE.md`
       → workspace `CLAUDE.md`. Engine `codex` → `adapters/codex/AGENTS.md`
       → workspace `AGENTS.md`.

    5. **Launch.** `cd "$HOME/.sherman/workspace"` then `exec "$ENGINE" "$@"`.
       `exec` so signals and exit codes pass straight through; `"$@"` so
       `sherman -p "..."` and friends work.
  </action>
  <verify>
    `bash -n bin/sherman` parses clean.
    End to end under a throwaway HOME with a stub engine:

  </verify>
  <done>AC-2, AC-3, AC-4, AC-5, AC-6 satisfied.</done>

<task type="auto">
  <name>Task 3: install.sh, smoke.sh, and the commit</name>
  <files>install.sh, smoke.sh</files>
  <action>
    **install.sh** — `#!/usr/bin/env bash`, `set -euo pipefail`, resolves its
    own directory so it works from anywhere.

    1. `chmod +x bin/sherman` (and `smoke.sh`).
    2. Pick a PATH directory by walking a priority list, first hit wins:
         `$HOME/.local/bin`  →  `$HOME/bin`  →  `/usr/local/bin`
       A candidate qualifies if it exists and is writable, **or** if its parent
       is writable so the script can create it.

       Deviation from the brief, deliberately: the brief named `~/bin` or
       `/usr/local/bin`. On this machine neither exists, `/usr/local/bin` is on
       PATH but absent from disk and would need sudo to create, and
       `~/.local/bin` is both on PATH and where `claude`, `codex` and `hermes`
       already live. Leading with `~/.local/bin` matches the machine's actual
       convention while keeping both named directories as fallbacks. The brief's
       real requirement — detect and report — is preserved and strengthened.

    3. `ln -sfn "$ROOT/bin/sherman" "$DIR/sherman"`. `-f` makes reinstall
       idempotent, `-n` stops it nesting a link inside an existing link dir.
    4. **Report** the chosen directory, and check whether it is on `$PATH` with
       a `case ":$PATH:" in *":$DIR:"*)` test. If not, print the exact
       `export PATH=...` line to add to their shell rc — do not fail, just say
       so clearly.
    5. Close with how to run it: `sherman`.

    Re-running must be silent-safe: no duplicate links, no error, same report.

    **smoke.sh** — exactly 3 checks, no framework. `set -uo pipefail` (not
    `-e`; checks must be able to fail and still report). Keep a failure counter,
    print `PASS`/`FAIL` per check, exit non-zero if any failed.

    Check 1 — `test -x bin/sherman`.

    Check 2 — first-run flow, fully sandboxed:
      - `TMPHOME=$(mktemp -d)`, `STUB=$(mktemp -d)`
      - write `$STUB/claude` as a stub that `exit 0`s; `chmod +x`
      - `printf '1\nsmoke tester\n' | env HOME="$TMPHOME" PATH="$STUB:$PATH" bin/sherman`
      - assert `$TMPHOME/.sherman/config.json` parses under `/usr/bin/jq` and
        that `.engine == "claude"`, `.user == "smoke-tester"`, `.vault_path`
        is a non-empty string
      - assert `$TMPHOME/.sherman/../..`-relative nothing: **the real `$HOME`
        is never touched.** Guard this explicitly — fail loudly if
        `$TMPHOME` is empty or unset before running, so a bad expansion can
        never point the run at the real home directory.

    Check 3 — reuse check 2's `$TMPHOME`. Read
    `$TMPHOME/.sherman/workspace/CLAUDE.md` and assert it contains: the vault
    path from the config, the string `smoke-tester`, and the string `patient`.
    Also assert the literal `{{SHERMAN_BODY}}` is **absent** — proof the splice
    ran rather than the template being copied through.

    Clean up both temp dirs with a `trap ... EXIT`.

    **Then commit.** Run `./smoke.sh` and require it green first. Stage only
    this plan's files — `install.sh bin/ agent/ adapters/ smoke.sh .gitignore`
    and `.paul/`. Do **not** stage anything under `logo/` or `vault/`; that is
    the parallel session's to commit.

    Commit message, subject plus body explaining the shape:

        Sherman Phase 1: launcher chassis

        `sherman` on PATH shows the banner, then execs the user's own coding
        CLI with an adapter assembled fresh each launch from agent/SYSTEM.md
        plus the vault memory blocks and the no-PHI rule.

        One persona, two thin adapters — engine-specific text lives only in
        adapters/, so the either-engine promise stays real.

        No custom OAuth: the provider question picks the engine, and that
        engine's own native login handles auth.

    Local commit only. **Do not push** (PROJECT.md C5).
  </action>
