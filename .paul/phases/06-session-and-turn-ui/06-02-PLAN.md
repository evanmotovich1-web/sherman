<objective>
## Goal

Copy the STRUCTURE of the Hermes mid-conversation screen in Sherman's palette:
each user turn as a bulleted line, a live activity trace underneath it while
the engine works, Sherman's reply in a bordered box with the mark and the word
"Sherman" set into its top border, and a segmented status bar — engine+model,
running session tokens, session minutes, turn timer while working, last turn
duration after — styled in the red family.

## Purpose

The shell already holds an honest conversation; it does not yet *stage* one.
Hermes' turn rendering makes the wait legible (you watch the agent work) and
makes authorship unmistakable (the reply is visibly the agent's, boxed and
signed). Evan asked for exactly that structure, under the same honesty rule
that governs the launch screen: every activity line and every status segment
comes from a real event or a real clock, or it does not appear.

## Output

- Turn rendering: `● <user text>`, dim italic activity trace from real events,
  bordered + labeled Sherman reply box
- Status bar: red-family segments, all true; no ctx-percent (transport reports
  none), no invented segments
- ONE new smoke check: a scripted turn through a fake backend, asserted on the
  bullet, the box label, and an activity line sourced from a fake event
</objective>

<facts_probed_at_plan_time>
Probed on ink 7.1.1 / react 19.2.8 / node v22.23.1, 2026-07-26.

1. **The fake-stdio harness works.** Ink 7 reads stdin via `'readable'` +
   `stdin.read()` — NOT `'data'` events, so the classic testing-library-style
   EventEmitter fake does nothing. A real `PassThrough` with `isTTY = true`
   and `setRawMode/ref/unref` stubs, plus a `PassThrough` stdout with
   `columns/rows`, drives the REAL interactive App off-TTY: writing `'\r'`
   reached `useInput`, a `<Static>` item committed, and the captured output
   contained it. This is the smoke mechanism for the scripted-turn check.
   Strip ANSI with `/\x1b\[[0-9;]*[A-Za-z]/g` before asserting (cursor moves
   use letters beyond `m`).

2. **Text-in-border alignment verified** (see 06-01 fact 1) — the Sherman box
   label uses the same composed-top-line + `borderTop:false` construction.

3. **`italic` works:** `<Text italic dimColor>` emits `\e[3m\e[2m`.

4. **The transport reports NO context-window figure.** `turn.completed.usage`
   carries input / cached_input / output / reasoning only (probed at 04-01,
   STATE). Therefore the ctx-percent segment DOES NOT EXIST in this plan. If a
   future transport (app-server) reports it, the segment earns its place then.

5. **No token deltas on this transport (D8).** "Streamed text fills the box"
   is item-level today: the box commits complete when the `message` event
   arrives. The construction must not fake a typewriter.

6. **The normalized event union already carries everything the trace needs**
   (`reasoning` text, `tool` label, `turn-start/end`, usage) — this plan
   touches nothing under `shell/src/engine/` (R12 holds).

## AC-1: User turns render as bullets
```gherkin
Given the user submits "check the intake SOP"
When the turn commits to the transcript
Then it renders as `● check the intake SOP` — bullet in the red family,
     text in the user colour — replacing the old "you" label row
```

## AC-2: The activity trace is live, styled, and NEVER invented
```gherkin
Given the engine emits reasoning and tool events during a turn
When the shell is working
Then a live line under the user bullet shows the latest activity dim + italic
     with the elapsed turn timer, and each real event commits a dim italic
     trace line (`thinking` text from reasoning events, labels from tool
     events) indented under the bullet

Given a turn during which the backend emits NO tool or reasoning events
When the shell is working
Then the trace shows only "thinking… <elapsed>" — no fabricated file names,
     no fabricated tool lines, nothing the engine did not report
```

## AC-3: Sherman's reply arrives in a signed box
```gherkin
Given a message event completes
When the reply commits
Then it renders inside a rounded box, border in the red family, whose top
     border embeds the mark glyph and the word "Sherman" (same construction
     as the version header), user bullet outside and above the box
And the text appears when the transport delivers it — item-level today (D8),
    with no simulated streaming
And box width follows the panel rule (min(columns - 2, 76)), long lines wrap
    inside the box, and nothing exceeds the terminal width
```

## AC-4: The status bar is segmented, red, and entirely true
```gherkin
Given the shell is idle after N turns
When the status bar renders
Then it shows, in the red family with dim separators:
     <engine> · <model> | <session token total> tokens | session <minutes>m |
     last <last turn duration>s
And while a turn is working the last segment is the LIVE turn timer instead
And NO ctx-percent segment exists (the transport reports no context figure —
    probed fact 4), and no segment without a real data source appears
And user + vault leave the bar (they live on the launch identity block now)
```

## AC-5: The scripted-turn smoke check proves the structure off-TTY
```gherkin
Given the fake-stdio harness (probed fact 1) mounting the REAL App over a
      fake EngineSession whose send() yields turn-start, reasoning, one tool
      event with a known label, message, turn-end

Then the captured output contains the user bullet line, the Sherman box label
     in a border line, and the fake tool label as a trace line
And ./smoke.sh totals 11 checks, all green
```
