<objective>
## Goal

Ship `skills/0-1/` — the skill Sherman reaches for **unprompted** when a request
needs a capability it does not currently have. It identifies the missing
connector, verifies the thing actually exists, wires it through the 08-01
catalog when no human is required, and stops with one precise account-and-key
checklist when one is.

## Purpose

Every other Sherman skill assumes the capability is already there. Nothing today
turns *"I want to do X"* into *"Sherman can now do X"* — the gap between an idea
and the connector it needs is currently a conversation the operator has to drive
themselves, and Sherman's honest "I can't reach that" is a dead end rather than
a next step.

`0-1` is the name for crossing that gap: zero capability to one. It is the skill
that makes the connector layer worth building, and it is the reason 08-01's
catalog carries a `signup` field.

## Output

- `skills/0-1/SKILL.md` — invocable as `/0-1`, auto-reachable by description
- One paragraph in `agent/SYSTEM.md` making capability-acquisition part of the
  operating contract rather than a skill nobody remembers to call
- smoke check 25
</objective>

## AC-1: /0-1 invokes it, and the engine can reach it unprompted

```gherkin
Given skills/0-1/SKILL.md declares name: 0-1 in its front matter
When   the operator types /0-1 in the shell

And    given a request needs a capability Sherman lacks
Then   the description is written so the engine reaches for it without being told
```

## AC-2: It wires what it can without asking

```gherkin
Given a request needs a connector that requires no credential — a local stdio
      server, a public MCP endpoint, an unauthenticated API
When   0-1 runs
Then   it verifies the connector really exists and really launches, adds it to
       agent/connectors.json, enables it in ~/.sherman/connectors.json, and
       reports what it did and that a relaunch activates it — without asking
       permission for the routine work the request already authorized
```

## AC-3: It stops with a checklist, not an interview, when a human is required

```gherkin
Given the needed connector requires an account or an API key
When   0-1 reaches that point
Then   it emits ONE message naming the service, the signup URL, the tier or plan
       to pick, the exact credential to create, and where to put it back
And    it does not ask a follow-up question, present a menu, or re-ask anything
       the request already answered
```

## AC-4: It never invents a connector

```gherkin
Given 0-1 is considering a connector, MCP server, or API
When   it cannot verify from a real source that the thing exists and takes the
       shape it plans to write
Then   it says the capability could not be sourced and proposes what it checked
       — rather than writing a plausible catalog entry that fails at launch
```

## AC-5: The boundaries hold

```gherkin
Given 0-1 handles credentials and adds external reach
When   it runs
Then   no secret value is echoed, logged, written to the repo, or written to the
       vault; no PHI crosses any connector it adds; and it never enables a
       connector whose purpose is to move patient data
```

          4. Send it to me and I will put it in <path> as <SECRET_NAME>.

<boundaries>

## DO NOT CHANGE

- `shell/src/commands.js` COMMANDS — `0-1` is a SKILL, not a first-party
  command. It rides the skill palette that already exists. Adding it to COMMANDS
  would make it a shell capability that the skill directory does not define, and
  the two registries mean different things (registry.js's header says so).
- `shell/src/engine/` — untouched, as in every phase since 05.
- `agent/connectors.json` — 08-01 owns its shape and its one seeded entry. This
  plan teaches Sherman to write entries; it adds none itself, because a
  speculative entry is exactly what AC-4 forbids.
- The adapter wrapper templates — shared persona goes in SYSTEM.md once.

## SCOPE LIMITS

- No credential UI, no key prompt in the shell. `0-1` names the file and the
  variable; the operator puts the key there. A shell that collects secrets is a
  shell that has to be trusted with them, and that is a bigger decision than
  this plan.
- No automatic installation of arbitrary packages from the internet. `0-1` may
  add a CATALOG ENTRY for a connector; it does not `npm install -g` unknown code
  into the operator's machine on its own initiative.
- No changes to `capability-gap` or `tool-audit`. They are cross-referenced, not
  rewritten.
