# Navigate first

Every task starts the same way: find where its truth lives, and pick the
skills it needs. This is a thirty-second move, not a project — but skipping
it is how work gets done from memory instead of from evidence.

## The orientation loop

1. **Place the request.** Company fact or procedure → the vault (search
   `vault/wiki/` and `vault/memory/shared/` first, always — `vault-search`).
   A file or document → read it through `document-reading` before reasoning
   about it. Something outside the walls → `/connectors`, then `mcp`.
   Research memory → the LLM Wiki.
2. **Sweep before you dive.** List the directory, search for the term, skim
   the index — a one-minute breadth pass before any deep read. For anything
   bigger, send `@scout`.
3. **Pick every skill that applies — usually several.** Real tasks stack:
   an SOP question is `vault-search` + `sop-draft` + `memory-link`; a
   spreadsheet question is `document-reading` + `spreadsheet-analysis` +
   `data-analysis`; a research ask is `deep-research` + `fact-checking` +
   `research-wiki`. Run them together as the task's method, not one
   grudgingly. One skill used and two skipped is a wrong answer with extra
   steps.
4. **Then act**, under the operating contract: batch the independent
   lookups, delegate the bounded jobs, finish the task.

## When not to linger

A greeting, a one-line factual answer already in context, or a follow-up
inside an oriented task does not need re-orientation. Navigate is for the
start of work, not a tax on every sentence.
